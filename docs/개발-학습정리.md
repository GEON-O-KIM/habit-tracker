# 습관 트래커 개발 학습 정리 (비개발자용)

이 문서는 "습관 트래커" 앱을 만들고, 아이폰에 설치하고, 인터넷에 올리기까지의 과정을
비개발자가 이해할 수 있도록 개념·용어·뜻과 함께 정리한 것입니다.

---

## 0. 우리가 한 일 (전체 흐름)

| 단계 | 한 일 | 결과물 |
|---|---|---|
| 1 | 화면과 기능을 코드로 작성 | `index.html`, `style.css`, `script.js` |
| 2 | "참음 횟수" 기능 추가, 디자인 조정 | 코드 수정 |
| 3 | 아이폰에 앱처럼 설치되도록 설정 (PWA) | `manifest.json`, `sw.js`, 아이콘 |
| 4 | 코드를 Git으로 기록하고 GitHub에 업로드 | GitHub 저장소 |
| 5 | GitHub Pages로 인터넷에 무료 공개 | https://geon-o-kim.github.io/habit-tracker/ |

## 1. 웹페이지의 3층 구조

웹페이지는 세 가지 언어가 각자 역할을 나눠 맡습니다. 집을 짓는 것에 비유할 수 있습니다.

| 언어 | 역할 | 비유 | 이 프로젝트의 파일 |
|---|---|---|---|
| **HTML** | 구조 (내용, 뼈대) | 벽과 방 배치 | `index.html` |
| **CSS** | 표현 (색, 크기, 배치) | 페인트, 가구 배치 | `style.css` |
| **JavaScript (JS)** | 동작 (반응, 계산, 저장) | 전기 배선, 스위치 | `script.js` |

- **HTML** (HyperText Markup Language): 제목, 문단, 버튼, 입력칸 같은 "내용"을 정의합니다.
- **CSS** (Cascading Style Sheets): 그 내용이 "어떻게 보일지" (색상, 여백, 정렬)를 정의합니다.
- **JavaScript**: 버튼을 눌렀을 때 "무슨 일이 일어날지" (숫자 증가, 화면 갱신, 데이터 저장)를 정의합니다.

> **왜 나눌까?** 역할이 분리되어 있으면, 디자인만 바꾸고 싶을 때 CSS만 건드리면 되고,
> 기능만 고칠 때 JS만 건드리면 됩니다. 서로 영향을 덜 줍니다.

## 2. 프로젝트 파일 지도

| 파일 | 종류 | 하는 일 |
|---|---|---|
| `index.html` | HTML | 앱의 화면 구조. 브라우저가 가장 먼저 읽는 파일 |
| `style.css` | CSS | 색상, 여백, 카드 모양, 애니메이션 |
| `script.js` | JavaScript | 습관 추가/삭제, D-day 계산, 저장, 화면 다시 그리기 |
| `manifest.json` | 설정 파일 | 앱 이름, 아이콘, 전체화면 실행 설정 (PWA용) |
| `sw.js` | JavaScript | "서비스워커". 오프라인에서도 열리도록 파일을 캐시 |
| `icon-192.png` / `icon-512.png` | 이미지 | 홈 화면 아이콘 (안드로이드/일반용) |
| `apple-touch-icon.png` | 이미지 | 아이폰 홈 화면 아이콘 (180px) |
| `README.md` | 문서 | 저장소 설명. GitHub 첫 화면에 표시됨 |

- **확장자** (extension): 파일 이름 뒤 `.html`, `.css`, `.js` 부분. 파일의 종류를 나타냄.
- **`.json`** (JavaScript Object Notation): 데이터를 적어두는 표준 형식. 사람이 읽기 쉬운 "이름: 값" 구조.
- **`.md`** (Markdown): 기호 몇 개로 제목·목록·표를 표현하는 가벼운 문서 형식. 지금 읽는 이 문서도 Markdown입니다.
- **`.png`** (Portable Network Graphics): 투명 배경을 지원하는 이미지 형식.

## 3. HTML 개념

### 3-1. 태그, 요소, 속성

```html
<button class="btn" id="save">저장</button>
```

- **태그** (tag): `<button>` 처럼 꺾쇠로 감싼 표시. 보통 여는 태그 `<button>` 와 닫는 태그 `</button>` 가 쌍을 이룹니다.
- **요소** (element): 여는 태그 + 내용 + 닫는 태그 전체 (`<button>저장</button>`).
- **속성** (attribute): 태그 안에 적는 추가 정보. `class="btn"`, `id="save"` 처럼 `이름="값"` 형태.
- **`id`**: 페이지에서 딱 하나만 있어야 하는 고유 이름표. JS가 특정 요소를 콕 집을 때 사용.
- **`class`**: 여러 요소에 붙일 수 있는 분류 이름표. CSS가 "이 분류에 해당하는 것 전부"를 꾸밀 때 사용.

### 3-2. 문서의 뼈대

```html
<!DOCTYPE html>       <!-- 이 문서는 최신 HTML이라는 선언 -->
<html lang="ko">      <!-- 문서 시작, 언어는 한국어 -->
  <head> ... </head>  <!-- 화면에 안 보이는 정보: 제목, 글꼴, 설정 -->
  <body> ... </body>  <!-- 화면에 실제로 보이는 내용 -->
</html>
```

- **`<head>`**: 브라우저와 검색엔진에게 주는 정보. 페이지 제목(`<title>`), 스타일시트 연결, 아이콘 등.
- **`<body>`**: 사용자가 눈으로 보는 모든 것.
- **`<meta>` 태그**: 페이지에 대한 메타데이터(데이터에 대한 데이터). 예: 문자 인코딩, 모바일 화면 대응.
- **`viewport`** (뷰포트): 모바일 브라우저에게 "화면 너비에 맞춰 표시하라"고 알려주는 설정.
  `<meta name="viewport" content="width=device-width, initial-scale=1.0">`

### 3-3. 시맨틱 태그 (의미가 있는 태그)

- **`<header>`**: 상단 영역 (제목, 요약)
- **`<section>`**: 하나의 구역 (습관 추가 폼, 습관 목록)
- **`<footer>`**: 하단 영역 (초기화 버튼)

`<div>` (의미 없는 상자)를 써도 되지만, 의미 있는 태그를 쓰면 코드를 읽기 쉽고
화면낭독기(시각장애인용 보조기기)도 구조를 이해합니다.

### 3-4. 폼 요소

- **`<form>`**: 사용자 입력을 묶는 상자. "제출"(submit) 이벤트가 발생함.
- **`<input>`**: 입력칸. `type="text"`(글자), `type="number"`(숫자) 등.
- **`<button type="submit">`**: 폼을 제출하는 버튼.
- **`placeholder`**: 입력칸에 흐리게 보이는 안내 문구 ("습관 이름을 입력하세요").
- **`required`**: 비어 있으면 제출을 막는 속성.

## 4. CSS 개념

### 4-1. 규칙의 생김새

```css
.habit__name {      /* 선택자: 무엇을 꾸밀지 */
  font-size: 17px;  /* 속성: 값  →  글자 크기 */
  font-weight: 700; /* 속성: 값  →  굵기 */
}
```

- **선택자** (selector): 꾸밀 대상을 고르는 표현.
  - `.클래스이름` → 그 class를 가진 요소들
  - `#아이디` → 그 id를 가진 요소 하나
  - `태그이름` → 그 태그 전부 (예: `body`)
- **속성** (property): 바꿀 항목 (`color`, `padding` 등).
- **값** (value): 그 항목에 줄 설정 (`red`, `16px` 등).
- **선언** (declaration): `속성: 값;` 한 줄.

### 4-2. 박스 모델 (Box Model)

모든 요소는 사각형 상자이고, 4겹으로 되어 있습니다. (안 → 밖)

1. **content** (내용): 글자나 이미지 자체
2. **padding** (안쪽 여백): 내용과 테두리 사이 공간
3. **border** (테두리): 상자의 선
4. **margin** (바깥 여백): 다른 상자와의 거리

- **`box-sizing: border-box`**: "너비를 계산할 때 padding과 border를 포함하라"는 편의 설정.
  이걸 안 하면 너비 계산이 헷갈립니다. 그래서 보통 코드 맨 위에 전체 적용합니다.

### 4-3. 배치: Flexbox

```css
.habit__buttons {
  display: flex;   /* 자식들을 가로로 나란히 */
  gap: 8px;        /* 자식들 사이 간격 */
  flex-wrap: wrap; /* 공간 부족하면 다음 줄로 */
}
```

- **Flexbox** (플렉스박스): 요소들을 가로 또는 세로로 정렬하고 간격을 배분하는 방식.
- **`gap`**: 자식 요소들 사이의 간격. margin보다 다루기 쉬움.
- **`justify-content`**: 主축(가로) 방향 정렬. `space-between`(양끝으로), `center`(가운데) 등.
- **`align-items`**: 교차축(세로) 방향 정렬.

### 4-4. CSS 변수 (커스텀 속성)

```css
:root {
  --accent: #4f7cff;   /* 색상 이름을 하나 정해둠 */
}
.btn { color: var(--accent); }  /* 그 이름을 불러 씀 */
```

- **CSS 변수**: 자주 쓰는 값(주로 색)에 이름을 붙여 한 곳에서 관리.
  나중에 `--accent` 한 줄만 바꾸면 앱 전체 색이 바뀝니다.
- **`:root`**: 문서의 최상위. 여기에 변수를 정의하면 어디서든 쓸 수 있음.
- **`#4f7cff`**: 색상을 나타내는 **16진수(hex) 코드**. `#RRGGBB` = 빨강·초록·파랑의 세기.

### 4-5. 반응형 & 다크모드

- **반응형** (responsive): 화면 크기(폰/태블릿/PC)에 따라 레이아웃이 달라지는 것.
- **미디어 쿼리** (media query): "이 조건일 때만 이 CSS를 적용" 하는 문법.
  ```css
  @media (min-width: 960px) { /* 화면이 960px보다 넓을 때만 */ }
  ```
- **`prefers-color-scheme`**: 사용자가 기기를 다크모드로 쓰는지 감지하는 조건.
- **단위**:
  - `px` (픽셀): 화면의 점 하나. 절대 크기.
  - `%` (퍼센트): 부모 요소 대비 상대 크기.
  - `em` / `rem`: 글자 크기 기준 상대 단위.
- **`env(safe-area-inset-*)`**: 아이폰의 노치·둥근 모서리를 피해 여백을 주는 값.

### 4-6. 애니메이션

```css
@keyframes resist-bump {
  0%   { transform: scale(1); }     /* 시작: 원래 크기 */
  45%  { transform: scale(1.18); }  /* 중간: 1.18배 커짐 */
  100% { transform: scale(1); }     /* 끝: 원래대로 */
}
```

- **`@keyframes`**: 애니메이션의 "이 시점엔 이 모습" 을 정의.
- **`transform: scale()`**: 요소를 확대/축소. `scale(1.18)` = 18% 크게.
- **`transition`**: 값이 바뀔 때 부드럽게 변하도록 하는 설정 (예: 진행바 너비).
- **`prefers-reduced-motion`**: 사용자가 "움직임 줄이기"를 켰는지 감지. 접근성 배려.

## 5. JavaScript 개념

### 5-1. 값을 담는 그릇: 변수

```js
var count = 0;          // count 라는 이름에 0 을 담음
count = count + 1;      // 1 로 바뀜
```

- **변수** (variable): 값을 담아두고 이름으로 부르는 것.
- `var`, `let`, `const` 세 가지 선언 키워드가 있음 (`const`는 안 바뀌는 값).

### 5-2. 자료 구조: 배열과 객체

```js
// 객체 (object): "이름: 값" 묶음. 습관 하나를 표현
var habit = {
  name: "아침 운동",
  goalDays: 30,
  violationCount: 3,
  checkedDates: ["2026-08-27", "2026-08-28"]  // 배열
};

// 배열 (array): 순서 있는 목록. 습관 여러 개를 담음
var habits = [habit1, habit2, habit3];
```

- **객체**: 하나의 대상이 가진 여러 정보를 묶음. `habit.name` 처럼 점으로 꺼냄.
- **배열**: 같은 종류의 것들을 순서대로 담은 목록. `habits[0]` 처럼 번호로 꺼냄 (0부터 시작).
- **속성/키** (property/key): 객체 안의 각 항목 이름 (`name`, `goalDays`).

### 5-3. 동작을 묶는 것: 함수

```js
function resistHabit(id) {        // "resistHabit" 이라는 동작 정의
  var habit = findHabit(id);
  habit.resistCount += 1;         // 참음 횟수 +1
  saveHabits(habits);             // 저장
  render();                       // 화면 다시 그림
}
```

- **함수** (function): 여러 줄의 명령을 하나의 이름으로 묶은 것. 필요할 때 이름만 부르면 실행.
- **매개변수/인자** (parameter/argument): 함수에 넘겨주는 입력값 (`id`).
- **호출** (call): 함수를 실행시키는 것 (`resistHabit("123")`).
- **`+= 1`**: "현재 값에 1을 더해 다시 넣어라" 의 줄임 표현.

### 5-4. 화면을 조작하는 것: DOM

- **DOM** (Document Object Model): 브라우저가 HTML을 읽어 만든 "요소들의 나무 구조".
  JS는 이 나무를 읽고 바꿔서 화면을 변경합니다.
- **`document.getElementById("habitList")`**: id로 요소 하나를 찾아옴.
- **`document.createElement("div")`**: 새 요소를 만듦 (아직 화면엔 없음).
- **`element.appendChild(child)`**: 만든 요소를 화면 나무에 붙임.
- **`element.textContent = "..."`**: 요소 안의 글자를 바꿈.
- **`element.classList.add("is-active")`**: 요소에 class를 추가 (CSS로 모양이 바뀜).

### 5-5. 사용자 반응 처리: 이벤트

```js
button.addEventListener("click", function () {
  // 버튼이 클릭되면 이 안이 실행됨
});
```

- **이벤트** (event): 사용자의 행동 (클릭, 입력, 폼 제출 등) 또는 브라우저의 상황.
- **`addEventListener("click", ...)`**: "클릭이 일어나면 이 함수를 실행해줘" 라고 등록.
- **콜백** (callback): 나중에 어떤 일이 생겼을 때 실행되도록 넘겨주는 함수.
- **`e.preventDefault()`**: 브라우저의 기본 동작을 막음 (폼 제출 시 새로고침 방지).

### 5-6. 데이터 저장: localStorage

```js
localStorage.setItem("habits", JSON.stringify(habits)); // 저장
var saved = JSON.parse(localStorage.getItem("habits")); // 불러오기
```

- **localStorage**: 브라우저가 제공하는 작은 저장 공간. 새로고침·재부팅해도 남음.
  단, **그 브라우저·그 기기 안에서만** 유지됨 (다른 폰과 동기화 X).
- **직렬화** (serialization): 객체/배열을 저장 가능한 "문자열"로 바꾸는 것 → `JSON.stringify`
- **역직렬화** (parsing): 저장된 문자열을 다시 객체로 되살리는 것 → `JSON.parse`

### 5-7. 판단과 반복

```js
if (elapsed < 0) elapsed = 0;   // 조건문: 만약 ~라면

habits.forEach(function (habit) {  // 반복문: 목록의 각 항목마다
  listEl.appendChild(buildCard(habit));
});
```

- **조건문** (`if`): 어떤 조건이 참일 때만 실행.
- **반복문** (`forEach`, `for`): 목록의 모든 항목에 같은 작업을 반복.
- **비교 연산자**: `<`(작다), `>`(크다), `===`(같다), `!==`(다르다).

### 5-8. 날짜 다루기

- **`new Date()`**: 지금 시각을 담은 객체.
- 이 앱은 시·분·초를 버리고 **"YYYY-MM-DD" 문자열**로 날짜를 다룹니다 (자정 기준 통일).
- **D-day 계산**: 두 날짜를 밀리초로 바꿔 뺀 뒤 하루(86,400,000밀리초)로 나눔 → 며칠 차이.

### 5-9. 기타 등장한 것

- **`"use strict";`**: JS를 더 엄격하게 검사하는 모드. 실수를 빨리 잡아줌.
- **IIFE** (즉시 실행 함수): `(function(){ ... })();` 코드 전체를 감싸 바깥과 격리.
  변수 이름이 다른 스크립트와 충돌하지 않게 함.
- **주석** (comment): `//` 또는 `/* */` 로 적는 설명. 실행되지 않음. 사람이 읽는 메모.

## 6. 이 앱의 작동 원리

### 6-1. 데이터 모델 (습관 하나의 구조)

```js
{
  id: "1724...",         // 고유 번호 (겹치지 않게 생성)
  name: "아침 운동",       // 습관 이름
  goalDays: 30,           // 목표 일수
  streakStartDate: "2026-08-28",  // 현재 연속 도전 시작일
  violationCount: 3,      // 어긴 총 횟수 (리셋 안 됨)
  resistCount: 12,        // 참은 총 횟수
  checkedDates: [...],    // "오늘 완료" 체크한 날짜 목록
  createdAt: "2026-08-01" // 만든 날
}
```

- **데이터 모델** (data model): "이 앱이 다루는 정보가 어떤 항목들로 이뤄지는가" 의 설계도.

### 6-2. 상태(state)와 렌더링(render)

이 앱의 핵심 규칙: **데이터가 바뀌면 → 저장하고 → 화면을 처음부터 다시 그린다.**

```
사용자가 "참음" 클릭
  → resistCount 를 +1        (상태 변경)
  → localStorage 에 저장      (영구 보존)
  → render() 실행             (화면을 데이터에 맞게 다시 그림)
```

- **상태** (state): 지금 이 순간 앱이 들고 있는 데이터.
- **렌더링** (rendering): 데이터를 보고 화면(HTML)을 만들어내는 것.
- 장점: "화면의 이 숫자만 몰래 바꾸기" 같은 실수가 없음. 항상 데이터가 진실이고 화면은 그 사진.

### 6-3. D-day 규칙

- **일차**: `오늘 - streakStartDate + 1` → 시작한 날이 `D+1`, 그다음 날 `D+2` …
- **목표일**: `goalDays - 일차` → `목표까지 D-N` 으로 표시.
- **하루 진행바**: 0시부터 지금까지 지난 시간을 % 로. 20초마다 갱신, 자정에 0으로.
- **어김 버튼**: `streakStartDate` 를 오늘로 되돌림 → 일차가 `D+1` 로 즉시 초기화.
  동시에 `violationCount` +1, 참음 캐릭터도 초기화.
- **참음 버튼**: 오늘의 `resistCount` +1 (하루 단위, 자정·어김 시 초기화).

### 6-4. 하위 호환 (마이그레이션)

"참음 횟수" 기능은 나중에 추가했습니다. 그 전에 만든 습관 데이터에는 `resistCount` 항목이 없습니다.
그래서 앱을 켤 때 이런 코드가 돕니다:

```js
habits.forEach(function (h) {
  if (typeof h.resistCount !== "number") h.resistCount = 0; // 없으면 0으로 채움
});
```

- **마이그레이션** (migration): 데이터 구조가 바뀔 때, 옛 데이터를 새 구조에 맞게 보정하는 것.
- **하위 호환** (backward compatibility): 새 버전이 옛 데이터·환경에서도 문제없이 도는 성질.

## 7. PWA: 웹을 앱처럼 만들기

### 7-1. PWA란

- **PWA** (Progressive Web App): 웹 기술(HTML/CSS/JS)로 만들었지만,
  홈 화면 아이콘·전체화면 실행·오프라인 동작 등 "앱 같은" 경험을 주는 웹사이트.
- 앱스토어 심사·설치가 필요 없음. 주소만 있으면 됨.

### 7-2. manifest.json (앱 정보 카드)

```json
{
  "name": "습관 트래커",
  "short_name": "습관",
  "display": "standalone",
  "background_color": "#f4f5f7",
  "theme_color": "#4f7cff",
  "icons": [ ... ]
}
```

- **매니페스트** (manifest): 앱의 이름·아이콘·색상·실행 방식을 적은 설정 파일.
- **`display: "standalone"`**: 주소창 없이 독립 앱처럼 실행하라는 뜻.
- **`theme_color`**: 상단 상태바 색.

### 7-3. 서비스워커 (sw.js)

- **서비스워커** (service worker): 웹페이지와 별도로, 브라우저 뒤에서 도는 작은 스크립트.
  네트워크 요청을 가로채 **캐시(저장해둔 사본)** 로 응답할 수 있음 → 오프라인에서도 앱이 열림.
- **캐시** (cache): 빠른 재사용을 위해 파일을 미리 저장해둔 것.
- **캐시 버전** (`habit-tracker-v1`): 파일을 수정하면 이 이름을 `v2`로 올려야
  서비스워커가 "새 파일"로 인식하고 갱신함. 안 올리면 옛 화면이 계속 보임.
- **`install` / `activate` / `fetch` 이벤트**: 서비스워커의 생애주기.
  설치될 때 파일을 캐시하고(install), 옛 캐시를 지우고(activate), 요청을 가로챔(fetch).

### 7-4. 아이폰 관련

- **`apple-touch-icon`**: 아이폰이 홈 화면 아이콘으로 쓰는 이미지 (PNG, 180×180 권장).
- **`apple-mobile-web-app-capable`**: 아이폰에서 전체화면 실행을 허용하는 옛 메타 태그.
- **"웹 앱으로 열기"** (Open as Web App): 아이폰 "홈 화면에 추가" 시 나오는 옵션.
  켜면 독립 앱으로 실행되고, **Safari 본체와 저장 공간이 분리**됨.
- **HTTPS 필요**: 서비스워커는 보안 연결(HTTPS)에서만 동작. 그래서 인터넷에 올려야 함
  (`localhost` 는 예외).

## 8. Git과 GitHub: 코드 저장과 배포

### 8-1. Git (버전 관리 시스템)

- **Git**: 코드의 변경 이력을 기록·관리하는 도구. "이 시점으로 되돌리기" 가 가능.
- **저장소** (repository, 레포): Git이 이력을 관리하는 프로젝트 폴더.
- **커밋** (commit): 그 순간의 코드 상태를 이름표(메시지)와 함께 기록한 "저장 지점".
- **스테이징** (staging, `git add`): 이번 커밋에 포함할 변경사항을 골라 담는 것.
- **브랜치** (branch): 독립적으로 작업하는 갈래. 기본 브랜치 이름은 보통 `main`.

```
git init            # 이 폴더를 Git 저장소로 만듦
git add -A          # 모든 변경을 스테이징
git commit -m "..." # 메시지와 함께 커밋(기록)
```

### 8-2. GitHub

- **GitHub**: Git 저장소를 인터넷에 올려두고 공유·백업하는 웹 서비스.
- **원격 저장소** (remote): 인터넷에 있는 저장소 사본. 기본 별명은 `origin`.
- **`git push`**: 내 컴퓨터의 커밋을 원격(GitHub)으로 올림.
- **`git pull`**: 원격의 변경을 내 컴퓨터로 내려받음.
- **공개/비공개** (public/private): 공개는 누구나 볼 수 있음. GitHub Pages 무료 사용은 공개 저장소.
- **`gh`**: GitHub 공식 명령줄 도구(CLI). 터미널에서 저장소 생성·설정을 함.

```
gh repo create habit-tracker --public --source=. --push
```

### 8-3. GitHub Pages (무료 웹 호스팅)

- **호스팅** (hosting): 파일을 서버에 올려 인터넷에서 접속 가능하게 하는 것.
- **GitHub Pages**: GitHub 저장소의 파일을 그대로 웹사이트로 공개해주는 무료 기능.
- **정적 사이트** (static site): 미리 만들어진 HTML/CSS/JS 파일만으로 도는 사이트.
  서버 프로그램이나 데이터베이스가 없음. 이 앱이 딱 이 경우 (그래서 무료 호스팅 가능).
- 결과 주소: `https://<사용자명>.github.io/<저장소명>/`

### 8-4. 그 밖의 용어

- **CLI** (Command Line Interface): 글자 명령으로 컴퓨터를 다루는 방식 (터미널).
- **터미널** (terminal): 명령어를 입력하는 검은 창.
- **URL**: 웹 주소. `https://` (프로토콜) + 도메인 + 경로.
- **HTTP 상태 코드**: 서버 응답 번호. **200** = 정상, **404** = 페이지 없음, **500** = 서버 오류.
- **배포** (deploy): 만든 것을 실제 사용 가능한 환경에 올리는 것.
